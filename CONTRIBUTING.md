### Getting Started

**Prerequisites:** Node.js 18+, Git, npm

```bash
# 1. Fork the repository
# 2. Clone your fork
git clone https://github.com/YOUR-USERNAME/jsputer-proxy.git
cd jsputer-proxy

# 3. Install dependencies
npm install

# 4. Create a feature branch
git checkout -b feature/amazing-feature

# 5. Make your changes and test
npm start  # Verify the server starts correctly
npm run lint  # Check for syntax errors

# 6. Commit and push
git commit -m "feat: add amazing feature"
git push origin feature/amazing-feature

# 7. Open a Pull Request
```

### Ways to Contribute

- 🐛 **Bug Reports** — Use the [Bug Report template](https://github.com/mulkymalikuldhrs/jsputer-proxy/issues/new?template=bug_report.md)
- 💡 **Feature Requests** — Use the [Feature Request template](https://github.com/mulkymalikuldhrs/jsputer-proxy/issues/new?template=feature_request.md)
- 🌍 **Translations** — Use the [Translation template](https://github.com/mulkymalikuldhrs/jsputer-proxy/issues/new?template=translation.md)
- 📝 **Documentation** — Fix typos, add examples, improve clarity, write tutorials
- 🔧 **Code** — New providers, routing logic, performance, security, features
- 🎨 **Design** — Improve README, badges, diagrams, visual elements
- 🧪 **Testing** — Write unit tests, integration tests, benchmark tests

### Development Process

1. Create a feature branch from `main`
2. Make small, focused commits
3. Write descriptive commit messages (Conventional Commits)
4. Keep your branch updated with `main`
5. Test before submitting your PR
6. Document any new features or changes

### Submitting Changes

1. Ensure your code follows the style guidelines
2. Run `npm run lint` to check for syntax errors
3. Update documentation if needed (README.md, PROVIDERS.md, API.md, TUTORIAL.md)
4. Describe your changes in the PR template
5. Request review from maintainers
6. Be responsive to feedback

### Style Guides

**JavaScript:** ES Modules (`import`/`export`), async/await, 2-space indentation

**Git Commits:** Conventional Commits format
```
type(scope): subject

feat(models): add support for new-model
fix(router): fix auto-routing for code tasks
docs(readme): update model list
feat(providers): add new provider adapter
```

**Types:** `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `perf`
